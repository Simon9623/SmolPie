1. SmolVLA 設計哲學與全局定位

為什麼機器人領域需要 450M 等級的 VLA 模型？

Foundational Concept

過去兩年，具身智能領域以 RT-2 (55B)、OpenVLA (7B)、π0 (3.1B) 等大型多模態動作模型為主導。然而，這類超大模型在實體機器人部署中面臨難以跨越的三大硬體鴻溝：

⏱️

推理延遲過高

7B+ 自回歸模型單次推理需 150~500ms，無法配合機器人本體需要 20~50Hz 的閉環反應頻率，遇到外力干擾極易脫軌。

💰

算力成本巨大

通常需要配備雙 A100/H100 工作站才能進行端側推理，一般實驗室或消費級機械臂（如 SO-100、Aloha）難以普及負擔。

📉

連續動作離散化精度損失

傳統 VLA 將連續關節角粗暴離散化為 256 個 Token 進行自回歸分類，導致軌跡抖動且無法進行精準微幅控制。

SmolVLA 的核心突破策略

  • 剪枝視覺語言骨幹 (Pruned SmolVLM2)： 將原生 32 層的 SmolVLM2-500M 剪枝為前 16 層，並將視覺輸入（512×512）藉由 Pixel-Shuffle Resampler 壓縮至僅 64 個視覺 Token，大幅降低注意力計算量。
  • 雙流分離解耦 (Asymmetric Dual-Stream)： 感知大腦（VLM）與動作小腦（Action Expert）分開。視覺語言只計算一次前綴（Prefix），產生 KV Cache；輕量級動作專家（僅 98M）獨立迭代生成連續動作軌跡。
  • 連續向量場流匹配 (Flow Matching Denoising)： 取代離散動作 Token，利用條件流匹配技術直接在連續動作空間進行向量場學習，僅需 10 步歐拉積分（Euler Step）即可生成長度 50 步的平滑動作分塊（Action Chunk）。
  • 即時動作分塊 (Real-Time Chunking, RTC)： 引入執行視界（Execution Horizon）與剩餘動作軌跡導引，解決非同步推理期間機械臂移動造成的邊界突變。
  • 階層式子任務規劃 (Hierarchical Subtask Tokens)： 支援以 <subtask>...</subtask> 進行兩段式解耦——由 SmolVLM 透過 Teacher Forcing 學習自回歸步驟推理，產生的子任務 Token 再透過交叉注意力引導 Action Expert 執行精準流匹配動作。
💡 性能與資源平衡亮點

在 LeRobot 的各類基準測試（如 Aloha Sim、SO-100 Pick-and-Place）中，450M 的 SmolVLA 展現出與數十億參數 VLA 旗鼓相當的任務成功率（50 次演示微調即可達 >70% 成功率），但訓練時僅需單張消費級 RTX 3090/4090 或 A10G 即可在 4 小時內完成 20,000 步收斂！

2. 雙流異構架構深度剖析

視覺語言骨幹 (SmolVLM2) 與動作專家 (Action Expert) 的協同機制

Core Architecture
圖 1：SmolVLA 雙流端到端架構全景圖（完整繪製 SmolVLM 骨幹、Subtask AR 解碼、FAST 動作預熱頭、與 Action Expert 交叉注意力流）

核心模組詳細職責與規格

1. 視覺語言大腦 (SmolVLM2)

負責高層環境感知與任務語義理解：

  • 視覺編碼 (SigLIP 12L)： 隱藏維度 768，自帶 12 頭。圖像 Top-Left padding 縮放至 512×512，正規化至 [-1, 1]。
  • Pixel-Shuffle 降採樣： 1024 個 patch 激進壓縮成僅 64 個特徵 Token (Hidden 960)，降低顯存與注意力負擔。
  • 剪枝文字模型 (16L)： 原始 SmolVLM2 截斷為前 16 層。在推理時前綴僅在 Step 0 計算一次 KV Cache。
  • 自回歸子任務頭： 透過 lm_head 支援自回歸解碼 <subtask>...</subtask>。

2. 動作專家小腦 (Action Expert)

負責基於條件特徵生成高精度的連續動作軌跡：

  • 非自回歸 Llama 變體架構： 擁有 16 層，採用 0.75 寬度乘數（`expert_width_multiplier=0.75`），隱藏維度 720，SwiGLU 中間維度 2048，參數量約 98.2M。
  • 交錯式 SA / CA 注意力： 偶數層為動作 Token 間自注意力（建立關節動力學相依）；奇數層為交叉注意力（檢索 VLM 前綴 KV 快取）。
  • 連續流匹配去噪： 利用 10 步歐拉數值積分，從高斯噪聲直接生成 50 步平滑的關節動作分塊。

3. FAST 離散動作輔助頭

Stage-1 訓練專屬的具身空間預熱頭：

  • 獨立動作詞表 (Vocab 2048)： 來自 Physical Intelligence FAST 分詞器，完全獨立於語言詞表。
  • 模組參數： 包含 fast_token_embed (2048 → 960) 與 fast_action_head (960 → 2048)，參數量約 3.93M。
  • 動作感知預熱： 在 Stage-1 透過離散動作分類交叉熵損失，強迫 VLM 骨幹在微調前就建立對機器人關節幾何空間的敏感度。
  • 推理零開銷切除： 推理部署時完全切除，不參與任何運算，不增加端側延遲！
💡 深度架構解析：階層式子任務 Token 究竟是如何「傳入」Action Expert 的？

問：直傳序列 Token × 還是 跨模態前綴 KV Cache 交叉注意力 ✓？

在概念直覺上，大家容易想像 Action Expert 會把「子任務 Token」直接當作輸入序列的一部分（如前綴在動作 Token 之前）。但 SmolVLA 的代碼實作採用了更為優雅且算力極致的「前綴 KV 快取交叉注意力橋接（KV Cross-Attention Bridging）」：

  • Action Expert 根本沒有語言詞表嵌入層（self.lm_expert.embed_tokens = None）： Action Expert 的隱藏維度是 720，而 VLM 語言嵌入維度是 960，動作小腦本身無法直接解析自然語言文字。
  • 空間圖文深度對齊在前，小腦檢索在後： subtask_tokens 先在 SmolVLM 內部與相機視角影像、全局指令、狀態進行 16 層跨模態注意力運算，將「抓取紅色積木」等子任務語義與相機像素特徵融合，轉化為高階鍵值矩陣（KV Cache）。
  • 10 步歐拉積分中每一步都被子任務條件約束： Action Expert 的奇數層（1, 3, 5, ...）透過 forward_cross_attn_layer，以動作 Token 為 Query (720d)，跨模態檢索包含子任務特徵的 Key/Value Cache (320d)。因此，子任務 Token 的語義資訊在每一層去噪中都 100% 傳入並約束著 Action Expert！

前綴與後綴注意力量表 (2D Attention Masking Pattern)

SmolVLA 採用自定義的 2D 塊狀因果注意力遮罩（Block-wise Causal Attention Mask），精確控制不同模態資訊的單向與雙向可見性：

⚠️ 實測代碼驗證：動作後綴 (Action Chunk) 嚴格遵循「因果單向 (Causal) 注意力」！

在直覺上容易誤以為 Flow Matching 既然是同時去噪 50 步，動作之間就會像影像一樣雙向互看；但經過 LeRobot 源代碼實測，動作 Token 之間在 Self-Attention 層嚴格採用下三角因果遮罩（Lower-Triangular Causal Mask）！

為什麼採用因果注意力而非全雙向？
1. 時序因果約束（Temporal Causality）： 在真實物理控制中，時間點 $t$ 的關節狀態必然只能受到歷史動態 $0 \le \tau \le t$ 的物理推動，嚴禁未來軌跡點向過去「時間逆向穿越（Future Leakage）」，否則會破壞馬達的真實運動學預測。
2. Prefix-LM 統一大架構： 繼承自 BigVision / OpenPI 的標準設計，前綴為雙向注意力（`att_mask = 0`），後綴所有生成 Token 逐步累加（`att_mask = 1`），完美相容 RTC 邊界前綴引導。

4. Continuous Flow Matching 與即時分塊 (RTC)

直擊向量場歐拉積分與機械臂抗延遲軌跡平滑技術

Dynamics & Control

連續向量場流匹配 (Flow Matching Formulation)

SmolVLA 放棄了傳統 Diffusion 繁複的雜訊排程 (Noise Schedule) 與反向 SDE/ODE，改採形式極為優美的條件流匹配 (Conditional Flow Matching, CFM)：

1. 訓練目標 (Training Objective)

給定真實專家動作軌跡 $a \sim q(a)$ 與隨機高斯噪聲 $\epsilon \sim \mathcal{N}(0, I)$，定義線性向量插值軌跡：

x_t = t · ε + (1 - t) · a
u_t = dx_t / dt = ε - a

時間步 $t$ 自 Beta 分布採樣：$t \sim \text{Beta}(\alpha=1.5, \beta=1.0) \times 0.999 + 0.001$（偏好中等雜訊階段以強化學習動態）。模型預測速度場 $v_t$，損失函數即為均方誤差：

L_FM = E_{t, ε, a} [ || v_t(x_t, t; c) - (ε - a) ||^2 ]

2. 推理採樣 (10-Step Euler ODE Solver)

推理初始從純高斯噪聲 $x_1 \sim \mathcal{N}(0, I)$ 開始，設定步數 $N = 10$，步長 $dt = -1.0 / 10 = -0.1$：

For step k = 0 to 9:
  t = 1.0 + k · dt
  v_t = ActionExpert(x_t, t, KV_prefix)
  x_{t+dt} = x_t + dt · v_t
Return a_pred = x_0

在短短 10 步數值積分後，噪聲張量 $x_1$ 沿著神經網絡定義的直線向量場平滑收斂至確定性動作 $x_0$！

即時分塊平滑技術 (Real-Time Chunking, RTC)

在真實機械臂控制中，假設模型推理需消耗 $\Delta$ 毫秒（例如 50ms）。當新的一組動作 Chunk 計算完成時，機械臂在過去 50ms 內仍在執行上一組 Chunk 的動作。如果直接強制切換到新 Chunk 的第一步，關節將會產生劇烈的速度/加速度突變（Jerk）甚至觸發機械臂過載停機。

圖 3：RTC (Real-Time Chunking) 軌跡拼接邊界導引示意圖

RTC 算法內部實現細節 (`src/lerobot/policies/rtc/`)

  • 剩餘軌跡注入 (Leftover Tracking)： 當前推理啟動時，將上一組尚未執行完的剩餘動作 `prev_chunk_left_over` 連同當前估計的 `inference_delay` 傳入 `euler_integrate`。
  • 條件導引去噪 (`rtc_processor.denoise_step`)： 在 10 步去噪過程中，RTC 根據指數衰減排程 (`RTCAttentionSchedule.EXP`)，對新 Chunk 前段施加導引權重 (`max_guidance_weight=5.0~10.0`)，強迫新軌跡的起點物理平滑地銜接在上一 Chunk 的終端狀態上。

5. 階層式子任務 (Subtask Tokens) 與 FAST 離散輔助頭深度剖析

連通高層任務規劃（Subtask Planning）、Teacher Forcing 並行訓練與連續動作執行

Hierarchical VLA

在長序列多階段的複雜操作任務中（例如「打開微波爐、將盤子放入、關上門」），單一全域自然語言指令往往無法提供足夠密集的導引信號。SmolVLA 實作了一套前瞻性的雙階段階層式架構 (Hierarchical VLA)： 讓 SmolVLM 擔任高層「規劃大腦」輸出自然語言子任務，再由 Action Expert 擔任「執行小腦」進行連續關節流匹配控制。

1. 訓練階段：並行 Teacher Forcing

問：訓練時沒有在回圈中一步一步自回歸生成，如何學會自回歸？

就像預訓練 GPT-4 或 Llama 一樣，數據集中已經包含了標註好的 Ground-Truth 子任務標籤。因此，模型在 compute_stage1_losses 中施加 因果單向遮罩（Causal Mask），在單次前向傳播（One Forward Pass）中並行計算所有位置的下一個 Token 預測交叉熵損失（Next-Token Prediction）：

L_subtask = CrossEntropy(logits, subtask_tokens)

透過反向傳播更新 SmolVLM 的注意力層與 lm_head，大腦即可在毫秒級訓練中掌握「看圖說出當前步驟」的規劃能力，訓練效率是逐步解碼的數百倍！

2. 推理階段：自回歸解碼 → Expert 執行

實際端側部署時的兩段式閉環推進：

  1. 自回歸解碼子任務 (generate_subtask)： 以 <subtask> 起始，透過 SmolVLM 的 lm_head 逐字解碼（Greedy 或 Sampling），直到生成 </subtask> 結束符（例如產出「移動夾爪至藍色積木上方」）。
  2. 前綴快取 (KV Cache Prefill)： 將剛生成的子任務文字與影像、狀態拼接，一次性前進傳播取得包含子任務語義的 KV Cache。
  3. 小腦條件去噪： Action Expert 透過奇數層交叉注意力，檢索該子任務的 KV 特徵，在 10 步內去噪輸出 50 步連續動作軌跡！

    token_loss = F.cross_entropy(logits.reshape(-1, logits.shape[-1]), subtask_tokens.reshape(-1))

# 2. 推理階段：自回歸逐 Token 生成子任務 (modeling_smolvla.py#L965-L1043)
if self.config.condition_on_subtask:
    # 從 <subtask> 開始，逐步解碼直到 </subtask>
    subtask_tokens = self.generate_subtask(images, img_masks, lang_tokens, lang_masks, state)
    # 拼接至前綴並計算 KV Cache，再進入 10 步 Flow Matching 動作去噪

重要辨析：子任務 Token vs. FAST 離散動作 Token

Subtask Tokens (子任務文字標記)

  • 詞表： 共用 SmolVLM 原生自然語言詞表 (49,280+)。
  • 功能定位： 高層任務語義規劃（「夾取」、「旋轉」、「放置」）。
  • 推理生命週期： 在推理時真實自回歸生成，並實際輸入 Action Expert 作為控制約束。

FAST Action Tokens (離散動作分詞)

  • 詞表： 專屬 Physical-Intelligence/fast 2048 離散動作詞表。
  • 功能定位： Stage-1 預熱訓練輔助頭，迫使 VLM 骨幹在微調前建立對關節幾何空間的敏感度。
  • 推理生命週期： 推理時完全切除 (Pruned at Inference)，不會生成，亦不參與任何動作執行，零推理延遲！

7. 資料處理 Pipeline 與核心代碼導讀

完整的 Pre/Post Processor 與推理執行流程

Code & Execution

預處理 (Pre-Processor) 鏈條流程

在 `src/lerobot/policies/smolvla/processor_smolvla.py` 中，數據經過標準化的流水線處理：

  1. steps.rename_observations：重命名觀測鍵值以對齊預訓練權重要求。
  2. steps.add_batch_dim：若為單步環境轉移（EnvTransition），自動增加 Batch 維度。
  3. NewLineTaskProcessorStep()：確保自然語言指令字串結尾具有換行符 \n（SmolVLM 指令格式規範）。
  4. SubtaskBoundaryProcessorStep()：自動在子任務前後插入 <subtask> 與 </subtask> 特殊標記。
  5. TokenizerProcessorStep()：將指令使用 AutoTokenizer 分詞，長度限制為 48。
  6. steps.to_device：將全部張量轉移至指定計算設備（CUDA/MPS/CPU）。
  7. steps.normalize：根據數據集統計量（Dataset Stats）將狀態與動作進行標準化（MEAN_STD 或 MIN_MAX）。

後處理 (Post-Processor) 鏈條流程

  1. steps.unnormalize：將模型預測的標準化動作向量還原回真實世界數值。
  2. steps.to_cpu：將張量轉移回 CPU 內存供機械臂驅動程式消費。
  3. Aloha 關節與夾爪特殊變換 (`adapt_to_pi_aloha`)： 若使用 Aloha 機械臂，代碼會自動調用 `aloha_gripper_from_angular` 將弧度空間轉換回 Interbotix 線性夾爪空間，並將特定關節反向映射。

from lerobot.policies.smolvla import SmolVLAConfig, SmolVLAPolicy
from lerobot.datasets import LeRobotDataset
import torch

# 1. 載入預訓練 SmolVLA 模型權重
policy = SmolVLAPolicy.from_pretrained("lerobot/smolvla_base")
policy.to("cuda")
policy.eval()

# 2. 準備觀測環境數據
batch = {
    "observation.images.front": torch.randn(1, 3, 512, 512, device="cuda"),
    "observation.state": torch.zeros(1, 6, device="cuda"),
    "observation.instruction": ["pick up the blue lego block\n"],
}

# 3. 呼叫動作生成 (內部自動管理 Action Queue 佇列)
with torch.no_grad():
    # select_action 自動維護 50 步佇列，每次呼叫返回當前 1 步控制指令
    action = policy.select_action(batch)
    print("Generated single-step action shape:", action.shape)  # [6]
